# Marketing Board — Synthesizer Prompt

<!-- Loaded by commands/marketing-board.md at step 5. Versioned independently so the synthesis logic can evolve without touching the slash command body. -->

You have just received reports from all 8 marketing-board seats (or N−1 if one failed twice). Your job is to synthesize a **single Marketing Plan Memo** and append an Open Questions section generated by deep analysis — **both in the same Claude turn**.

## Inputs you now have

- All 8 (or N−1) agent reports, each opening with `## <Seat> Report` and following its per-seat sub-header skeleton.
- The framed brief from step 3.
- Any repo-aware context you read before dispatching.

## Synthesis steps

Execute these in order:

### S-1 — Read all reports

Read every agent report fully. Do not summarize from the first sub-header alone.

### S-2 — Extract one-line positions

Each agent's report has a designated "one-liner" sub-header (the synthesizer reads this for the verdicts table):

| Seat               | First sub-header to read |
| ------------------ | ------------------------ |
| Ethnographer       | `### One-line position`  |
| Storyteller        | `### One-line position`  |
| Channel Strategist | `### One-line position`  |
| Producer           | `### One-line position`  |
| Funnel Engineer    | `### One-line position`  |
| Community/PR Lead  | `### One-line position`  |
| Moonshot           | `### Reframing`          |
| Contrarian         | `### Verdict`            |

### S-3 — Populate the verdicts-at-a-glance table

8 rows (or N−1 with `[FAILED: <reason>]` for a failed seat). One column for seat name, one for the one-liner. Keep one-liners tight; the user can read the full report below the memo.

### S-4 — Identify convergent points

Where do multiple seats independently land on the same point? List 3-6 convergent observations. These are the parts of the plan with strong cross-lens support.

### S-5 — Identify conflicts

Where do seats actively disagree? **Attribute the positions to the seats taking each side.** Don't smooth tensions over — name them. This is the only place in the memo (apart from informal cross-references) where you call out seats by name.

### S-6 — Synthesize "The plan I'm proposing"

Write a single-voice, founder-facing plan. This is your judgment as the synthesizer, *informed* by the board but *not* a vote count. Specifically:

- Reflect the Storyteller's positioning and message house.
- Honor the Channel Strategist's mix and sequencing, calibrated by the budget envelope.
- Embed the Producer's flagship-asset cadence.
- Wire the Funnel Engineer's highest-leverage funnel fixes.
- Include the Community/PR Lead's community posture + launch surface picks.
- **Explicitly address the strongest Contrarian objection** — don't pretend it doesn't exist; either incorporate the mitigation or name what's being accepted.
- If the Moonshot's keystone bet is genuinely viable within the constraints, weave it in or explain why incremental is the right call here.

Single voice throughout — no "the Ethnographer said…" phrasing.

### S-7 — Accept risk explicitly

Lift the Contrarian's strongest objection into a short paragraph (1-3 sentences) under `## What I'm accepting as risk`. Frame it as the founder's eyes-open trade-off, not a dismissal.

### S-8 — Pre-launch checklist

Bullet list of must-haves before launch day, derived from cross-seat dependencies (e.g. "LP variants ready before PR pitches go out," "email sequences live before paid spend opens"). 5-10 items.

### S-9 — First 30 days, concrete actions

Numbered list, 3-7 items, drawn primarily from the Channel Strategist's sequencing, the Producer's first-month calendar, and the Community/PR Lead's launch-day sequence. Each item should be one a founder can actually do this week — not "build brand awareness."

### S-10 — Metrics to track

Table: `KPI | baseline (if known) | target window`. Pull KPIs from the Funnel Engineer's funnel map and the Channel Strategist's CAC expectations. 5-8 rows.

### S-10b — Carry the email-sequences outline

Copy the Funnel Engineer's `### Email sequences (outlines)` report block into the memo's `## Email sequences (outlines)` section, near-verbatim — tighten wording only, do not invent sequences the Funnel Engineer didn't propose. One subsection per sequence, each with: sequence name, trigger, target metric, email count, and a one-line outline per email. This section is the machine-readable contract the `/marketing-board:email-sequence` skill parses to draft full emails — keep the `### Email sequences (outlines)` / per-sequence structure intact. If the Funnel Engineer seat failed (and produced no report), omit the `## Email sequences (outlines)` section entirely.

### S-11 — Generate Open Questions (deep analysis, same turn)

After the memo body, append a `## Open Questions` section generated by deep analysis. **This step mirrors the prd-writer / tdd-writer skill Phase 2 verbatim** — same shape, same discipline.

**Inputs to your deep analysis:**

- The memo you just synthesized
- All 8 (or N−1) raw agent reports

**Reasoning depth:** ultrathink. Do not produce a quick OQ list — interrogate the memo and the underlying reports for genuine unresolved decisions.

**Focus on:**

- Ambiguities in the proposed plan
- Missing decisions the founder must make before execution
- Edge cases the board surfaced but didn't resolve
- Scope-boundary decisions (do this now vs. next quarter)
- Stakeholder-input needs (legal, partners, hires, budget approvals)

**Skip:**

- Cosmetic questions
- Hypothetical edge cases the brief doesn't motivate
- Questions already answered in the brief or knowledge base

**Numbering:** `OQ-01`, `OQ-02`, … per memo (not global). Aim for 3-8 OQs in most memos.

**Render shape (locked):**

1. **Intro line:**

    ```
    *Generated via deep analysis after synthesis — resolve before execution. Answer these in this file (tick the checkboxes), then run /marketing-board --consolidate to fold them in.*
    ```

2. **Summary table:**

    ```markdown
    | ID    | Question                                           | Status |
    | ----- | -------------------------------------------------- | ------ |
    | OQ-01 | <Question, one line>                               | Open   |
    | OQ-02 | <Question, one line>                               | Open   |
    ```

3. **One per-OQ detail block per row**, in exactly this shape:

    ```markdown
    ### OQ-NN — <Question title>

    **Question:** <one-sentence statement>

    **Why it matters:** <one line — what unblocks once resolved>

    **Possible answers:**

    - [ ] Option A — short rationale
    - [ ] Option B — short rationale
    - [ ] Option C — short rationale

    **Status:** Open  *(or `Deferred to v2` when applicable)*
    ```

    You may include a recommendation at the end of `**Status:**` (e.g. `Open — recommend Option B because Channel Strategist's CAC math favors it`), mirroring how this spec family handles OQ recommendations.

**Why the shape is locked**: the `--consolidate` flow parses this exact structure, and the user's habit (built up across PRD + TDD work) is keyed to it. Drift breaks both.

## Attribution convention

- **Single voice** in: `## Brief recap`, `## The plan I'm proposing`, `## What I'm accepting as risk`, `## Pre-launch checklist`, `## First 30 days — concrete actions`, `## Metrics to track`.
- **Attributed** (seat names called out) in: `## Where the board disagrees` and — informally, where it sharpens traceability — `## Where the board agrees`.
